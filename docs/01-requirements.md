# fin-news-v5 需求文档（PRD v1）

## 1. 背景与问题

A 股散户最真实的需求不是"看新闻"，而是**解释市场**：

1. 涨跌之后第一时间想知道"为什么"（归因），而不是看一堆无因果关系的标题流。
2. 现有的满足方式是早/晚刷微信财经大 V 公众号——他们的解释不一定专业，但"心理按摩 + 方向指引"很有效，用户黏性极高。
3. 大 V 是单向广播，不会回答"我的票怎么办""这个政策对半导体到底是利好还是利空"。

本产品的定位：**一个随时在线、能解释市场、能接追问的资讯分析 Agent。**

一句话价值主张：
> 及时告诉用户"现在市场是什么状态、为什么是这个状态、接下来关注什么方向"；用户想追问"为什么 / 怎么样"时，能基于当天全量资讯与市场数据继续追问。

## 2. 目标用户与使用场景

| 用户 | 特征 | 核心诉求 |
| --- | --- | --- |
| 散户（主要） | 非专业、持仓集中、情绪驱动、信息滞后 | 归因、方向感、持仓相关的直接结论 |
| 进阶个人投资者 | 看板块/产业链 | 板块传导路径、龙头与估值锚 |

典型场景：

- **S1 盘前（07:00–09:15）**：隔夜美股怎么样？外围发生了什么？今天 A 股大概率怎么开？关注哪些方向？
- **S2 盘中（09:30–15:00）**：某条快讯弹出（如"央行下调存款准备金率 50bp"），系统几分钟内给出评级 + 深度解读：影响什么板块、利好谁、逻辑链条是什么。
- **S3 盘后（15:00–18:00）**：今天为什么涨/跌/缩量震荡？主线是谁？明天看什么？
- **S4 追问（任意时刻）**："降准对我的半导体持仓有什么影响？""光模块这波还能追吗？" → 基于已入库资讯 + 行情做 RAG 问答。
- **S5 个股归因**：搜索某只票，看到与其相关的全部事件 + 每次事件的分析结论与估值/走势判断。

## 3. 术语表

| 术语 | 含义 |
| --- | --- |
| 资讯（news item） | 从数据源抓取的一条原始新闻/快讯/公告 |
| 评分（score） | 1–10 整数，衡量**该资讯对市场的影响程度**（非情绪、非重要性） |
| 分档（band） | 评分区间对应的处理策略：MACRO / INDUSTRY / STOCK / NOISE |
| 深度分析（analysis） | 评分后由对应 Agent 产出的结构化研报式结论 |
| 盘前/盘后简报 | 定时生成的当日市场展望 / 复盘报告 |
| 事件（event） | 模块间解耦的消息，落库为 `ingest_event`，由 pipeline 消费 |

## 4. 功能需求

### F1 资讯接入（Ingestion）— P0

- F1.1 从 Tushare 定时增量拉取资讯类数据。
  - `news`（新闻快讯，需单独开权限）：src ∈ {`sina`, `wallstreetcn`, `10jqka`, `eastmoney`, `yuncaijing`, `fenghuang`, `jinrongjie`, `cls`, `yicai`}；字段 `datetime / title / content / channels`。
  - `major_news`（长篇通讯，需单独开权限）：字段 `title / content / pub_time / src / src_site`，用于宏观政策类深度分析正文。
  - 行情与基本面（分析 Agent 的取数工具）：`daily`、`daily_basic`、`index_daily`、`us_daily`、`stk_forecast`、`top_list`、`top_inst`、`fina_indicator`、`trade_cal`、`stock_basic`、`anns` 等。
- F1.2 **每分钟**触发一次增量拉取（APScheduler），按 `(source, src)` 维护增量位点（cursor），支持重叠窗口（回看 N 分钟）以容忍数据源延迟。
- F1.3 归一化 + 去重：统一字段模型，按 `content_hash`（正文规范化后哈希，忽略标点与空白）与 `simhash` 判重。
  - 指纹计算前先剥离转载前缀（如 `【财联社9月1日电】`）；
  - 近似去重阈值经实测校准为**汉明距离 ≤ 10**（标点/前缀差异=0，截断=9，改 2 字=10，无关资讯=25）；
  - 重复资讯更新 `first_seen_at / seen_count`，不重复入库。
- F1.4 噪声过滤（规则层，廉价前置）：广告、荐股话术、纯行情速报、"X 股涨停/跌停"无因快讯、转载重复。
- F1.5 原始数据落库后发出 `news.ingested` 事件。

### F2 评分（Scoring）— P0

- F2.1 使用**轻量 flash 模型**对一批资讯（batch，建议 20–50 条/批）批量打分，输出 1–10 整数分 + 一句话理由 + 证据标签。
- F2.2 评分标准：**以"该资讯对市场的影响程度"为唯一标尺**，分档如下（分档边界采用左开右闭，见 §9 澄清项）：

| 分数区间 | 档位 | 定义 | 典型例子 |
| --- | --- | --- | --- |
| (7, 10] | `MACRO` 宏观/政策 | 影响面广、跨行业传导、改变流动性与风险偏好 | 央行降息/降准/加息；美联储加息降息/QE/缩表；能源价格大幅波动；突发（新）战争；日本央行政策转向；重大资本市场制度变革 |
| (5, 7] | `INDUSTRY` 行业/产业 | 影响一个产业链或板块 | 新能源、创新药、锂电、光模块、半导体、芯片产业链政策；有行业代表性的头部公司财报/预增；海外龙头（英伟达、海力士、三星、美光等）财报或事件 |
| (3, 5] | `STOCK` 个股事件 | 影响范围小，局限于单票或少数标的 | 龙虎榜、个股预增/预减、个股公告、订单中标、减持/回购、监管函 |
| (0, 3] | `NOISE` 常规/噪声 | 反映结果而非原因，或与市场无关 | 每日股市波动播报、收盘涨跌描述、社会/娱乐/体育等无关资讯 |

- F2.3 评分是**分档路由的依据**，同时作为前端信息流的排序权重。
- F2.4 每条资讯的评分结果可重算（模型升级/规则变更后批量重跑），保留历史评分记录。
- F2.5 评分后发出 `news.scored` 事件；**仅 `score > 3` 的资讯进入向量化**。

### F3 向量化入库 — P0

- F3.1 对 `score > 3` 的资讯做分块（chunk，建议 512–800 token，overlap 80），调用 Embedding 服务，写入 `news_chunk`（pgvector）。
- F3.2 嵌入文本包含标题 + 时间 + 来源 + 正文，元数据（news_id、score、band、发布时间、关联标的代码）随 chunk 存储，供检索时过滤。
- F3.3 入库完成后发出 `news.embedded` 事件，触发深度分析。

### F4 深度分析（Agents）— P0

按评分路由到不同 Agent，产物统一为结构化报告（含结论、逻辑链、标的/板块列表、置信度、风险提示）：

| Agent | 触发条件 | 输入 | 必须产出的内容 |
| --- | --- | --- | --- |
| `macro_policy_agent` | `score > 7` | 资讯全文 + **向量库历史检索**（同类政策的历史表现）+ **外部信息检索**（联网搜索补充背景/市场预期/海外反应） | 政策解读、流动性与风险偏好研判、传导路径、**受益板块清单**、**受损板块清单**、A 股/港股/美股映射、关键跟踪信号 |
| `industry_agent` | `5 < score <= 7` | 资讯全文 + 向量库历史检索 + 行业成分与行情/估值数据 | 事件对行业的量价与盈利影响、**行业头部公司筛选**、**估值分析**（PE/PB/PS、历史分位、同业对比）、行业景气判断 |
| `stock_agent` | `3 < score <= 5` | 资讯全文 + 个股行情 + 财务/估值 + 龙虎榜/资金流 | 事件对个股的影响、**估值分析**、技术走势与量价、风险与关注点 |
| `pre_market_agent` | 每交易日 **07:30**（可配）定时 | 隔夜美股（`us_daily`）+ 隔夜资讯（近 12h，score 加权）+ 大盘指数状态 | 外盘表现、隔夜要闻、今日 A 股展望、关注方向、风险提示 |
| `post_market_agent` | 每交易日 **15:30**（可配）定时 | 当日指数/涨跌家数/成交额/板块涨跌 + 当日全部资讯与评分 | **今日为什么涨/跌/震荡**（归因，按贡献度排序）、主线与轮动、资金面、次日关注 |
| `qa_agent` | 用户发起追问（S4） | 会话历史 + 向量检索 + 行情/估值工具 | 直接回答"为什么/怎么样"，引用来源，必要时反问澄清 |

- F4.1 分析 Agent 允许**多步工具调用**（历史检索、行情取数、联网搜索），由 DeepAgents 编排。
- F4.2 分析结果入库，并回写 `news_item.analysis_status`；同时产出简要摘要（1–3 句）供列表页展示。
- F4.3 每条分析保留模型、token 消耗、耗时、引用的资讯/外部来源，可追溯、可复现。

### F5 数据服务（REST API）— P0

见 `docs/04-openapi.md`。核心能力：资讯流（按分档/时间/来源/评分过滤）、分析详情、盘前/盘后简报、市场概览、语义检索、个股视图、追问会话。

### F6 Web 展示端 — P0（本期只做 Web）

React + TypeScript。页面：今日时间线（资讯流 + 评分 + 一句话结论）、深度分析详情、盘前/盘后简报、市场概览、语义搜索、个股详情、追问对话。移动端适配（响应式），为后续 Flutter App 复用同一 API。

### F7 iOS App（Flutter）— P2（本期不做）

API 契约先行，F5 保持端无关；后续 Flutter 端直接复用，不做 WebView 套壳。

### F8 运营与可观测 — P1

- 任务运行记录（`agent_run`）与事件队列可视化：成功率、耗时 P50/P95、失败原因 TopN。
- LLM 调用审计（`llm_call_log`）：模型、token、成本估算、失败率。
- 手动重跑/补数入口：指定时间区间重新拉取、指定资讯重新评分/重新分析。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 时效 | 从资讯发布到"评分 + 一句话结论"可见：P95 ≤ 3 min；深度分析：P95 ≤ 8 min |
| 可用性 | 数据服务 API 可用性 ≥ 99.5%；分析链路故障不阻塞资讯接入与阅读 |
| 一致性 | 全流程幂等：重复事件、重跑任务不产生重复分析；同一 `(news_id, agent_type)` 只保留一份生效报告 |
| 成本 | 评分走 flash 模型 + 批量；深度分析走强模型但受并发与预算上限约束；单条资讯日均 LLM 成本设软预算，超限降级（只保留摘要级分析） |
| 可扩展 | Agent、数据源、模型均可插拔配置；新增 Agent = 新增一个配置 + 一个 prompt/工具集合 |
| 可解释 | 所有结论必须给出依据（引用资讯 id / 数据字段 / 外部来源链接），禁止无源断言 |
| 合规 | 所有输出标注"AI 生成，不构成投资建议"；不输出具体买卖点位、不承诺收益 |

## 6. 数据源与模型

- **数据**：Tushare Pro（积分/权限决定可用接口；`news`、`major_news` 需单独开通资讯权限）。接入层做接口级降级：无权限或限流时记录 `ingest_cursor` 不前进，告警但不中断整体调度。
- **模型**：通过 OpenAI 兼容接口接入，支持运行时切换。
  - 火山引擎（Doubao）与 DeepSeek 双 Provider 配置化；
  - 角色化选型：`scoring`（flash/轻量）、`analysis`（强推理）、`embedding`（向量）、`qa`（均衡）；
  - 每个角色可配主/备模型，主模型失败自动降级。

## 7. 本期范围外（Out of Scope）

- 实盘交易、自动下单、持仓盈亏计算（不做券商账户对接）。
- 荐股与买卖点建议（只做影响分析与估值描述）。
- 用户注册体系（MVP 用匿名设备 ID，后续再接账号）。
- iOS/Flutter 端（本期仅 API 契约预留）。
- 实时行情推送（WebSocket），MVP 用轮询 + 分钟级任务。

## 8. MVP 验收标准

1. 每分钟增量拉取 ≥ 3 个资讯源，去重后入库，可回溯任意一天的资讯流。
2. 评分分布合理抽样人工校验：人工抽 100 条，分档一致率 ≥ 80%。
3. `score > 3` 的资讯 100% 有向量 + 100% 有对应 Agent 的结构化分析。
4. 交易日 07:30 / 15:30 自动生成盘前/盘后简报，且简报引用了当日 ≥ 5 条高评分资讯。
5. Web 端可完成 S1–S5 五个场景的闭环，追问回答带引用来源。
6. 断网/限流/模型超时注入测试后，系统无数据丢失（事件可重放）、无重复分析。

## 9. 方案澄清与默认决策（需确认）

| # | 疑点 | 本方案默认决策 |
| --- | --- | --- |
| 1 | 需求原文"入库后发事件 → 评分"与"评分后只对 score>3 做向量化入库"存在顺序矛盾 | **先落原始数据 → 发事件 → 评分 → score>3 才 chunk + embedding → 再发事件 → 深度分析**。理由：省 embedding 成本，且噪声不污染检索库 |
| 2 | 分档边界在 5/7 处未定义（`score > 5 && score < 7` 漏掉 `=5` 与 `=7`） | 采用**左开右闭**：`(7,10]` / `(5,7]` / `(3,5]` / `(0,3]`；`score <= 3` 不向量化 |
| 3 | 评分是否允许小数 | 评分输出 **1–10 整数**（批量评分稳定性更好），置信度单独给 0–1 浮点 |
| 4 | 深度分析是否必须联网 | 仅 `macro_policy_agent` 强制要求外部检索；行业/个股 Agent 可选启用（默认关闭以控成本） |
| 5 | 盘前/盘后任务是否在非交易日运行 | 否，依据 `trade_cal` 判断交易日；非交易日跳过并记录 |
| 6 | 向量维度 | 由配置 `EMBEDDING_DIM` 决定，必须与所选 Embedding 模型一致（火山 doubao-embedding 与 DeepSeek 侧需显式校准），建表时按配置生成 |
